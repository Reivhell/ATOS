# Agentic Trading OS v0.5.4 — Validation report

**Release decision: NOT PRODUCTION-READY / NOT RELEASE-CERTIFIED.**

This iteration adds release-artifact provenance and integrity verification. It does not claim that the desktop application has been built, that native Rust tests have run, or that dependencies are reproducibly locked.

## Implemented changes

1. `scripts/release-evidence.mjs` generates an unsigned JSON release manifest after the Tauri bundle exists. It records app version, full source commit, clean-tree assertion, timestamp, platform/architecture, available Node/npm/Rust tool versions, CI run identity, and a deterministic full artifact inventory.
2. The inventory hashes regular files and records symbolic links without following them. A symlink that resolves outside the bundle is rejected. Empty bundles, version mismatch, non-clean source trees, unsupported filesystem entries, and malformed inventory paths are rejected.
3. `checksums.json` contains SHA-256 digests for every bundle entry and the exact `release-manifest.json` bytes. The verifier re-enumerates the bundle and fails on changed bytes, changed link targets, added or removed artifacts, checksum mismatch, schema mismatch, and app-version mismatch. On GitHub Actions it also checks that the manifest commit matches `GITHUB_SHA`.
4. Tagged multi-platform CI now generates, verifies, and uploads the release evidence alongside each platform's bundle. Release evidence is explicitly unsigned; it is not publisher authentication, signed provenance, or a substitute for code signing.
5. Added seven dependency-free test cases covering exact hashes, inventory ordering, tampering, added files, checksum/manifest edits, empty output, version mismatch, nested output paths, internal symlinks, and symlink escape rejection.

## Production blockers that remain

- Run `npm ci`, frontend typecheck/build, Rust formatting, all native Rust tests, and Clippy on supported CI runners.
- Build the packaged Tauri application for each target OS and run desktop acceptance tests against the actual bundles.
- Add a signed provenance/attestation and verify publisher signing policy before treating the hash manifest as an authenticity control.
- The current analysis inventory has 364 catalog entries, but only 6 are Calculated, 1 is Workflow, and 357 are Catalog only. Agent dispatch integration has not been proven; live trading remains disabled.

## Interpretation

The release evidence implementation is an improvement over v0.5.3 because every tagged platform bundle can now carry a tamper-detectable, fully enumerated artifact record. Its Node logic is exercised locally, but the evidence generator has not run against a real Tauri bundle in this environment. This iteration therefore improves release traceability, not overall production certification.
