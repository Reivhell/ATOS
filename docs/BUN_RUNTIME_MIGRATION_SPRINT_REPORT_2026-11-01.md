## Baseline verified on `main` before migration

- The optional local research API already uses Bun and Hono. The package scripts include `dev:api` and `start:api` with Bun.
- A `bun.lock` lockfile is present.
- CI has a dedicated Bun compatibility job that installs from the frozen Bun lockfile, runs repository guardrails, runs the MJS test suite, and executes the Hono integration tests.
- The primary repository guardrails and full source test suite now use Bun scripts and Bun's test runner.
- Frontend build, Tauri dev/build commands, release evidence, installer staging, and attestation verification now invoke scripts through Bun. Both lockfiles remain required as a conservative transition safeguard.
- Release preflight now checks Bun and native toolchains, not Node/npm availability.
- The existing validation report says Bun/Hono runtime integration and native/release acceptance were not executed in the audited environment. CI configuration is not evidence that those checks have passed.

## Sprint scope

1. Make Bun the documented and automated default for JavaScript/MJS execution and test scripts.
2. Move CI's primary source-test and repository-guardrail path to Bun while retaining any Node compatibility checks that are demonstrably required by dependencies or tooling.
3. Align frontend build, Tauri CLI invocation, release-evidence commands, and release staging with Bun where supported.
4. Update release preflight and repository contract tests to enforce the intended runtime policy without weakening release gates.
5. Generate and verify the Bun lockfile using the actual Bun package manager; resolve whether npm lockfile retention is still required by the release policy.
6. Run the full Bun suite, Hono integration suite, frontend build, Rust checks, and release preflight in CI. Keep MT5 MetaEditor and broker acceptance as separate gates.

## Acceptance criteria

- A clean checkout installs dependencies with `bun install --frozen-lockfile`.
- All supported scripts and the complete MJS/API test suites pass under Bun in CI.
- CI and release commands no longer require Node/npm for tasks Bun can safely own; any remaining Node requirement is documented with a concrete toolchain reason.
- The committed lockfile is generated by Bun, and dependency changes fail on frozen-lockfile validation.
- Repository guardrails and their regression tests reflect the new runtime policy.
- Release preflight remains fail-closed and reports actual missing toolchains rather than bypassing checks.
- The report distinguishes CI-verified results from local or broker-specific checks that have not run.
